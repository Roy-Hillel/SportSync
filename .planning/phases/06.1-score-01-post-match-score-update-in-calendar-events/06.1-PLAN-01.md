## Objective

Extend the data layer to capture, store, and detect score changes for finished matches:

1. Add `home_score` and `away_score` nullable integer columns to the `sport_events` DB table
2. Add `homeScore` / `awayScore` nullable number fields to `ProviderEvent` (provider-agnostic domain type)
3. Map `goals.home` / `goals.away` from the API-Football fixture response in `mapFixture()`
4. Include scores in `hashEvent()` so the sync engine detects score changes as hash mismatches → updates
5. Propagate score fields through the engine's `toInsert` and `toUpdate` paths

This plan is pure data-layer work. No iCal output changes — those are in Plan 02.

### Task 5: Add scores to hashEvent() so score changes trigger DB updates

<read_first>
- `src/lib/sync/hash.ts` — full file; understand current payload construction
- `src/lib/providers/types.ts` — confirm `homeScore` / `awayScore` field names on `ProviderEvent`
</read_first>

<action>
In `src/lib/sync/hash.ts`, extend the `payload` array to include scores. Scores must be part of the hash so that when a match finishes and goals.home/away change from null to integers, the hash changes → sync engine writes the update.

Current payload:
```typescript
const payload = [
  event.startTime.toISOString(),
  event.homeTeamName,
  event.awayTeamName,
  event.competitionName,
  event.venue ?? "",
  event.status,
].join("|");
```

Updated payload — append score fields at the end (using empty string for null/undefined to keep hash stable):
```typescript
const payload = [
  event.startTime.toISOString(),
  event.homeTeamName,
  event.awayTeamName,
  event.competitionName,
  event.venue ?? "",
  event.status,
  event.homeScore != null ? String(event.homeScore) : "",
  event.awayScore != null ? String(event.awayScore) : "",
].join("|");
```

Using `!= null` (covers both `null` and `undefined`) ensures the hash is stable when scores are absent and changes when scores are populated.
</action>

### Task 6: Propagate scores through the sync engine (toInsert / toUpdate)

<read_first>
- `src/lib/sync/engine.ts` — full file; specifically the `syncEntity()` function and its `toInsert` / `toUpdate` construction
- `src/lib/db/schema.ts` — confirm `homeScore` / `awayScore` column names on `sportEvents.$inferInsert`
</read_first>

<action>
In `src/lib/sync/engine.ts`, update `syncEntity()` to write `homeScore` and `awayScore` to the DB in both the insert and update paths.

**Insert path** — add to `toInsert.push({...})` block, after `status`:
```typescript
homeScore: event.homeScore ?? null,
awayScore: event.awayScore ?? null,
```

**Update path (hash mismatch)** — add to `toUpdate.push({ id, values: {...} })` block, after `status`:
```typescript
homeScore: event.homeScore ?? null,
awayScore: event.awayScore ?? null,
```

The unchanged path (same hash) does NOT need to include scores — if the hash is unchanged, scores are unchanged too.

Also update the `from` window in `runFullSync()` to cover the last 3 days (to catch recently-finished matches whose scores haven't been captured yet):

Current:
```typescript
const now = new Date();
const to = addWeeks(now, 26);
```

Updated:
```typescript
const now = new Date();
const from = new Date(now.getTime() - 3 * 24 * 60 * 60 * 1000); // now - 3 days
const to = addWeeks(now, 26);
```

Then update the `syncEntity()` call to pass `from` instead of `now`:
```typescript
const entityResult = await syncEntity(entity, provider, from, to);
```

This ensures matches from the past 3 days are re-fetched so their final scores are captured.
</action>
